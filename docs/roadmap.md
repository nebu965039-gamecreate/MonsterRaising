# ドット絵モンスター育成ウィジェットアプリ 開発ロードマップ

## 全体方針

- Phase 1〜3で「育成の中枢」を固める(ここが崩れると後工程すべてに影響するため最優先)
- Phase 4以降でミニゲーム・フレンド機能を積み増し
- 身内(自分+友人)で運用しながら磨き込み → 広告実装 → 一般リリース

---

## Phase 1: DEMOキャラクター & 動作確認

**ゴール:キャラクターが画面内で動く状態を作る**

- [ ] 4頭身・斜め前(3/4視点)のドット絵DEMOキャラ1体を作成
- [ ] パーツ分割(体/頭/目/口/腕(奥・手前)/脚(奥・手前)/影/付属パーツ)
- [ ] 差分画像切り替え方式でのアニメーション実装(idle/食事/寝る 程度の最小セット)
- [ ] Jetpack Composeでの差分画像プレイヤー(JSON定義→画像切り替え)を試作
- [ ] 本体アプリ上での表示確認(ウィジェットはまだ考えない)

**成果物:1体のモンスターが本体アプリ上でパラパラ動く状態**

---

## Phase 2: ステータス設計

**ゴール:育成に必要なパラメータ体系を固める**

- [ ] ステータス項目の確定(例:満腹度/清潔度/機嫌/有効度 など、ミニゲーム成績で伸びる値も含む)
- [ ] ステータス変化のロジック(時間経過による減少、お世話による回復)
- [ ] 進化条件の設計(ステータスの累積・達成条件・経過時間の組み合わせ)
- [ ] 進化段階ごとの見た目差分(幼少期/成長期/成熟期)をDEMOキャラで1系統だけ作成し検証
- [ ] ローカルでのステータス永続化(端末内データ保存)

**成果物:お世話→ステータス変化→進化までの一連の流れが1系統で動く状態**

---

## Phase 3: ウィジェット表示

**ゴール:ホーム画面のウィジェットに育成状況を反映する**

- [ ] RemoteViews/Glanceでのウィジェット実装(状態ごとの静止画切り替え)
- [ ] ウィジェットタップで本体アプリに遷移する導線
- [ ] 定期更新の仕組み(WorkManager/AlarmManager)
- [ ] ウィジェット内の簡易アクション(餌やりボタンなど単発タップ操作)

**成果物:ウィジェットからモンスターの状態が見え、簡単なお世話ができる状態**

---

## Phase 4: ミニゲーム(第一弾:テトリス風)

**ゴール:育成と接続したミニゲームを1本作り切る**

- [ ] 落ち物パズルのコア実装(オリジナル形状・配色で設計)
- [ ] スコア→ステータス反映のロジック接続
- [ ] 独立モジュールとして実装(後続ミニゲーム追加時に影響が出ない構成)

**成果物:ミニゲームで遊んだ結果が育成に反映される状態**

---

## Phase 5: ミニゲーム(第二弾:カード×NPC戦)

**ゴール:運試し要素のあるミニゲームを追加する**

- [ ] オリジナルカード体系でのブラックジャック風ロジック実装
- [ ] NPCの複数体設計(勝ち上がり式)
- [ ] 育成ステータス反映(手札アドバンテージ、モンスターカード特殊効果など)
- [ ] 連勝数のローカル記録

**成果物:2種類のミニゲームが独立して遊べる状態**

---

## Phase 6: 身内テスト運用

**ゴール:自分+友人で実際に運用し、バランス調整する**

- [ ] Firebase Authenticationでの簡易ログイン実装
- [ ] Firestoreでのステータス・進化データの同期(端末間・友人間で共有できる最低限の構成)
- [ ] 身内グループへのテスト配布(APK直接配布 or Google Playの内部テストトラック)
- [ ] フィードバックをもとにステータスバランス・進化条件・ミニゲーム難易度を調整

**成果物:友人と一緒に遊べる、バランス調整済みのベータ版**

---

## Phase 7: フレンド機能

**ゴール:身内テストの手応えをもとにフレンド機能を本実装する**

- [ ] フレンド登録・フレンド一覧
- [ ] ログイン状況・ステータスの閲覧(表示ON/OFF設定つき)
- [ ] フレンドキャラのウィジェント内出現演出
- [ ] 定型メッセージ送付(FCM経由)
- [ ] プレゼント送付/お世話代行/応援スタンプ
- [ ] フレンド限定ランキング(連勝数・清潔度など)

**成果物:フレンドと緩く繋がる要素が一通り揃った状態**

---

## Phase 8: 広告実装・リリース準備

**ゴール:マネタイズを組み込み、一般公開できる状態にする**

- [ ] 広告SDK導入(バナー/インタースティシャル/リワード広告の使い分け設計)
- [ ] リワード広告と育成要素の接続(例:広告視聴でお世話ブーストなど)
- [ ] Firebase Blazeプランへの移行、Budget Alertsの設定
- [ ] プライバシーポリシー・利用規約の整備
- [ ] ストア掲載情報(スクリーンショット・説明文)の準備
- [ ] Google Play審査提出

**成果物:一般ユーザー向けに公開できる状態**

---

## Phase 9: 継続運用

**ゴール:リリース後の拡張運用の土台を作る**

- [ ] ミニゲームのローテーション配信の仕組み(Firebase Remote Config活用)
- [ ] 新規ミニゲームの追加(モグラたたき/3マッチパズル/属性マッチングなど)
- [ ] 進化パターンの追加、季節イベント対応
- [ ] ユーザーフィードバックの収集・反映サイクルの確立

---

## 優先順位の考え方

1. **Phase 1〜3(育成の中枢)** は絶対に妥協しない土台。ここが面白くないと以降の要素が活きない
2. **Phase 4〜5(ミニゲーム)** は「テトリス→カード」の順で、実装が軽い方から着手すると勢いがつく
3. **Phase 6(身内テスト)** を挟むことで、フレンド機能や広告の実装前にコアの面白さを検証できる
4. **Phase 7以降** は身内の反応を見てから本腰を入れる、で手戻りを減らせる
